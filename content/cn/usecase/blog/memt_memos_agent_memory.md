---
title: "MemT-1.0 与 MemOS 如何分工？从一次编码任务开始选型"
---

![MemT-1.0 与 MemOS 选型](https://cdn.memtensor.com.cn/img/1793872135595_gjhz96_compressed.png)

Agent 修好了一个构建错误。下次遇到相似问题，它能不能少走一遍之前已经排除的弯路？

过了几天，项目又升级了依赖，启动命令也变了。Agent 既要用上之前的排查经验，也要知道现在该执行哪条命令。

[记忆张量MemTensor](https://memtensor.com/){target="_blank"} 的 MemT-1.0 将记忆引入模型计算，让历史信息能够以记忆状态参与后续任务；MemOS 则提供面向应用的记忆组织、检索与维护能力。把两者放在同一个工作流中看，更容易理解经验如何复用、变化的信息又如何继续被使用。

## 经验复用与事实更正，需要不同的操作

设想 Agent 曾经修好一个构建错误，留下两类信息。一类是排查经验：先检查依赖，再检查配置。另一类是项目事实：当前使用哪个运行时，部署命令是什么。

排查经验可以在新任务中帮助缩小搜索范围；项目事实一旦变化，就要让后续操作采用新值。把一份过期配置保存得更牢，并不会让构建更可靠。

因此，选择记忆方式时，可以先看信息将来要怎样使用。需要直接查看原文、引用来源和逐条更正的内容，保留可定位的记录；需要在后续任务中反复使用的排查方法，也可以整理成经验，由应用检索，或写入模型记忆状态供后续使用。

## MemT 改变经验怎样参与模型计算

[MemT-1.0 技术报告](https://arxiv.org/html/2610.26825v1){target="_blank"}描述了动态局部记忆与可训练的超记忆模块。历史信息进入记忆状态，后续生成读取这些状态，减少每次重新处理全部历史文本的需要。对持续多轮的任务来说，项目背景和历史交互可以通过记忆状态影响后续回答，不必在每次生成时一直保留全部历史文本。在技术报告的长历史实验中，128K tokens 历史长度下，MemT-1.0-Nano 的端到端推理速度约为完整上下文方案的 1.86 倍，单条轨迹的持久状态存储约为后者的 1/66。

训练阶段学习记忆机制，推理阶段则更新和使用动态状态。理解这个区别，才能正确设计评估：既观察同一历史下的后续表现，也观察历史变长时的处理开销。

固定容量的状态还涉及细节保留的取舍。技术报告在长历史效率之外，也讨论了细致检索历史证据的挑战。若任务要求找回合同原句或精确引用一次决定，可将原始材料作为可检索依据，同时评估模型如何利用压缩后的经验。

对于编码任务，可以进一步看：过去的经验是否改变了 Agent 处理新问题的方式？

在一次 Django 日期解析任务中，没有经验指导的 Agent 找到相关代码后较早开始修改；写入经验后，Agent 先建立复现测试，再修改代码。在 MemT-1.0-Nano 的执行轨迹中，Agent 还在修改后回头检查了边界条件，并进行了额外验证。

这组[编程实验](https://arxiv.org/html/2610.26825v1){target="_blank"}先从历史任务中整理可复用经验，再将相关经验写入模型记忆状态。在 SWE-bench Verified 的执行前写入设置下，MemT-1.0-Nano 的平均成功率为 69.33%，无经验基线为 66.07%；同一任务独立运行三次、全部成功的比例分别为 61.60% 和 54.00%。

对编码 Agent 来说，经验的价值不只体现在能否复述过去，还体现在它能否帮助完成新的工作。

## MemOS 让变化中的信息持续可用

[MemOS 生命周期管理](/cn/memos_cloud/introduction/mem_lifecycle/)覆盖记忆生成、使用、合并和清理；[修改接口](/cn/api_docs/core/update_memory/)提供按记忆 ID 更正内容的入口。项目规则因而可以成为能够检索、查看和更新的对象。

例如，团队将旧的手动启动步骤改成自动脚本。应用可以更新对应的记忆，记录新的启动方式、适用项目和版本；团队成员也可以通过[自然语言反馈](/cn/memos_cloud/mem_operations/add_feedback/)提交修正。

下一次构建时，应用检索与当前项目有关的记忆，把新的启动规则提供给 Agent。此前形成的排查经验仍然可以使用，同时需要按照新的项目条件判断哪些步骤适用。

| **信息** | **选型时优先观察什么** |
| --- | --- |
| 一次调试形成的方法 | 相似新任务是否更容易完成 |
| 当前命令与项目约定 | 能否找到当前值并及时更正 |
| 原始错误日志 | 能否定位原文和具体证据 |

同一工作流可以同时需要这些信息。例如，MemOS 可以将对话中的方法整理成可检索的 [Skill](/cn/memos_cloud/features/self-evolving/)，让 Agent 在相似任务中参考；对于使用 MemT 的应用，也可以将相关经验写入模型记忆状态，让经验参与后续生成。

项目命令和原始日志则可以继续以可定位的形式管理。这样，经验复用、事实更新和证据查询就能在同一个工作流中互相配合。

## 用一次条件变化判断方案是否适合

可以选一个真实仓库，准备连续三项任务：解决问题、复用方法、升级依赖。第三项让旧方法的某个前提发生变化，观察 Agent 是否改用新的规则。

比较时，尽量保持任务输入、工具环境和通过条件一致，记录实际完成情况、处理时间，以及是否需要人工重新解释。

对 MemT，可以对照有无相关经验时的任务表现，观察经验如何影响后续操作；对 MemOS，可以检查信息更新后，应用能否检索并使用新的项目规则。如果比较不同模型或不同接入方式，也要记录各自的配置，帮助解释结果。

还可以把同一经验放到另一个项目，检查其适用条件是否仍成立。将项目规则与个人偏好分开，并使用[项目和用户范围](/cn/memos_cloud/introduction/isolation_filters/)组织检索，能减少把相似背景当成相同要求。

这样得到的选择有明确理由：哪些信息值得压缩复用，哪些需要随时更正，哪些必须保留原文。记忆的价值最终体现在 Agent 下一次工作时少走弯路，也能跟上已经改变的事实。
